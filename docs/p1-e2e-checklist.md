# PookyBlog P1 서비스 검증

실제 서비스 구성(Web, post, post-read, user, comment, like, view, hot-post, Redis, Kafka)을 실행한 뒤 확인합니다. 화면에 검증용 게시글이나 통계를 주입하지 않습니다.

공유 Redis를 사용하는 환경에서 hot-post 통합 테스트를 실행하지 마세요. 테스트 프로필은 Redis 주소를 분리하지 않습니다. 통합 테스트는 별도 Redis/Kafka를 준비한 뒤 `POOKY_RUN_EXTERNAL_INTEGRATION_TESTS=true`로 명시적으로 활성화해야 합니다.

## 데이터와 장애 조건

1. 실제 계정으로 로그인하고 당일 게시글을 작성합니다. 게시글을 열고 좋아요와 댓글을 남깁니다.
2. 홈의 최근 글과 `지금 주목받는 글`을 확인합니다. 인기글은 당일(`yyyyMMdd`) 집계가 발생한 뒤에 표시됩니다. 집계 전에는 빈 상태 문구가 나와야 합니다.
3. hot-post 서비스만 중지하고 홈을 새로고침합니다. 최근 글은 유지되고 인기글 영역에 일시적 오류 문구가 나와야 합니다. 서비스를 다시 시작한 뒤 복구를 확인합니다.
4. 좋아요 한 게시글을 다시 열어 처음부터 선택 상태인지 확인합니다. 취소 후 새로고침하면 선택 상태가 사라져야 합니다. 로그아웃 상태에서는 로그인 안내가 보여야 합니다.

## 기능 회귀

- 목록, 상세, 조회수, 페이지네이션, 작성, 수정, 삭제
- 댓글 작성·수정·삭제, 좋아요·취소, 로그인·회원가입·로그아웃
- 존재하지 않는 URL과 게시글의 404, 백엔드 장애 상황의 500 화면 및 HTTP 상태
- 각 요청 후 브라우저 콘솔 오류와 네트워크 응답 상태

## 화면 폭

브라우저 개발자 도구에서 1440px, 1024px, 768px, 390px을 확인합니다. 각 폭에서 홈 Trending, 목록 metadata, 상세 action·댓글, 작성 폼, 페이지네이션, 404/500 화면을 살펴보고 `document.documentElement.scrollWidth <= document.documentElement.clientWidth`를 확인합니다.
